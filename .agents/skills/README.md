# Project Agent Skills

Curated skills imported for Oaken from the original repositories. These are optional task-specific guides; use them when their trigger fits, rather than loading every skill for every task.

## Installed skills

- **caveman** — concise communication while preserving technical detail. Source: [JuliusBrussee/skills](https://github.com/JuliusBrussee/skills/tree/main/skills/caveman)
- **interface-kit** — high-quality, accessible, performant UI implementation. Source: [JuliusBrussee/skills](https://github.com/JuliusBrussee/skills/tree/main/skills/interface-kit)
- **animate** — design and implement purposeful interaction motion. Source: [emilkowalski/skills](https://github.com/emilkowalski/skills/tree/main/skills/animate)
- **review-animations** — critique existing motion for craft and performance. Source: [emilkowalski/skills](https://github.com/emilkowalski/skills/tree/main/skills/review-animations)
- **emil-design-eng** — interaction polish, component details, and motion decisions. Source: [emilkowalski/skills](https://github.com/emilkowalski/skills/tree/main/skills/emil-design-eng)
- **break-ui** — test UI against awkward and extreme content. Source: [emilkowalski/skills](https://github.com/emilkowalski/skills/tree/main/skills/break-ui)
- **learn-taste** — convert design corrections into durable project rules. Source: [emilkowalski/skills](https://github.com/emilkowalski/skills/tree/main/skills/learn-taste)
- **pick-ui-library** — choose established libraries instead of hand-rolling common primitives. Source: [emilkowalski/skills](https://github.com/emilkowalski/skills/tree/main/skills/pick-ui-library)

## Oaken-specific guidance

- Follow the existing Oaken design system and supplied references; don't invent textures, ornament, or fantasy patterns.
- Use motion sparingly: purposeful, fast, interruptible, and reduced-motion aware.
- Prefer accessible, robust UI and test empty, long, missing, and unusually large data.
- Preserve the current branch workflow and do not modify the protected `vercel` branch.
- Keep `caveman` opt-in for terse replies; it should not change the project's normal communication style unless explicitly activated.
